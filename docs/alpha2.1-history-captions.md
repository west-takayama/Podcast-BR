# α2.1 履歴字幕の競合調査

## 再現条件

保存済み区間字幕がある回で、全文の保存と出演者名やタイトルの更新を同時に実行する。α2では履歴の読み取りと書き込みが別々のIndexedDBトランザクションだった。両方の処理が同じ古いレコードを読み、後から履歴の行全体を書いた更新が全文を消した。Chromeで同時更新を20回実行し、α2で20回全文が消え、α2.1で20回全文が残った。失われた全文を持つ旧版では、復帰時に区間字幕のキャッシュを選び得る。

## 修正

- ストアへの読み取りと書き込みを一つのトランザクションにまとめる。履歴確定後に字幕リビジョンを通知し、開いている編集画面を再初期化する。
- 字幕を使う前に最新の履歴を確認する。候補区間をカバーする全文を優先する。区間キャッシュはエピソード、原音リビジョン、開始・終了、字幕種別が一致したときに再利用する。
- 字幕補正後とエンコード後にもリビジョンを照合する。更新前の結果を字幕画面や完成動画として確定させない。同じ回を別タブで更新した場合は編集中の旧下書きと出力を画面から外す。
- 付け直したID3タグは原音の時間軸を変えない。素材を選び直した場合は、長さが似ていても既存字幕と送信済み素材への参照を自動では引き継がない。

## 回帰試験

`npm run dev -- --host localhost --port 4251 --strictPort` を起動し、`node e2e/history-caption-race.js` を実行する。合成素材の履歴を使い、単独20回と並行4コンテキストで20回の計40回を実行する。全文保存と出演者欄の競合、履歴再読み込み、開いた後の全文更新を検証する。各モードの初回で動画を書き出し、別タブで更新した際に旧動画リンクが消えることを確認する。Geminiの要求は捕捉し、1件でも発生すれば失敗とする。

既存の全体試験は `npm run build` に続けて `npm run e2e` を実行する。
