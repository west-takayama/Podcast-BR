# AI STUDIO 3.0 最終リリース準備

## 判定

正式公開は保留。iPhone実機のネイティブAAC/H.264、YouTube実取込、実ホスティングの保護、配布条件の最終承認が完了してから公開可否を判定する。月額予算上限2,000円を維持し、今回の追加固定費は0円。

## 本編・既刊ショート

- 360pを標準に維持する。YouTube公開実績を確認できない0.5fpsに代わり、公開資料が推奨するフレームレートの一つである24fpsを採用する。静止画1枚から、2秒の閉じたAVC GOPを一度だけ生成し再利用する。MP4/H.264とAACを用い、既存音声のビットレート設定は維持する。この実装でのYouTube処理成功は別途承認後の実試験を要する。[YouTube推奨設定](https://support.google.com/youtube/answer/1722171) · [YouTubeの取込トラブル対処](https://support.google.com/youtube/answer/58134)
- Safari 26.0のWebKit資料ではWebCodecsのAudioEncoder対応拡大が確認できる。機種や設定によるエンコード成功は実機で判断する。未対応を検出したときは、元の編集済み音源を同じバイト列で保存できる。対応端末または発行者が承認した端末内変換経路へ持ち出せる。FFmpeg AACの再配布は行わない。[WebKit Safari 26.0](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
- 履歴で既刊の音声・動画を開き、選抜後に「すでに公開したYouTube本編に紐づける」を開く。主宰者が公開を確認した動画ID／視聴URL、公開日時（JST）、タイトル、回番号を登録する。登録は端末内の確認記録。別の回で登録済みのID、予定日時、承認・配信処理中の本編を拒否する。本編を作り直さず、過去の公開先を使う。
- 履歴に元動画が残っていない場合は利用者が同じ元素材を選ぶ。親エピソードIDは維持する一方、新しく選んだファイルに古い字幕・アップロード状態を自動流用しない。同じ投稿先への同じ候補・バイト列・同一回の完全一致区間を拒否する。承認、公開確認、結果不明時の保留は既存の投稿台帳を維持する。実SNSの照合や端末横断の重複は手動確認も必要。

## iPhone試験と公開境界

主宰者は認証済みステージ用HTTPS URLをSafariで開く方式を優先する。今回は利用可能な既存URLを確認できず、管理APIへのアクセスも拒否された。外部に新しい試験サイトは作っていない。公開URLが準備できるまでは非公開試験キットを技術担当が別オリジンで起動する。主宰者側の操作はSafariの認証、画面のボタン操作、合成ファイルの選択に絞る。LAN方式では信頼されたTLS証明書とステージ端末の設定が必要。試験キットの起動は[RC1の非公開試験手順](rc1-release-qa.md)に従う。

1. Safariでステージの `iphone-codecs.html` を開き「端末で確認する」。安全な接続、H.264 360p/24fps、AAC 1ch/2ch、保存領域を記録する。入力は合成静止画と無音だけ。アカウント接続・外部通信は不要。
2. 同じステージで合成の編集済みMP3を選び、360pで書き出す。最初・中間・最後で画像と音を確認する。失敗時は「編集済み音源をそのまま保存」で元データの保存を確認する。長尺は待ち時間を別記録する。
3. 履歴で既刊素材を確認。既存本編を登録し、ショートの承認と結果不明時の保留を合成データで確認する。別の回に同じ本編IDを入れると拒否されることを確認する。
4. シークレットブラウザーまたは未認証クライアントで実AUDIOホストのトップ、JS、マニフェスト、固定音源の直URLを見る。全て401/403か認証画面で保護され、応答に実素材が含まれないことが必須。試験キットでの同試験と、実ホストの照合は別項目。
5. 実機が通ってから、YouTube取込を別承認で行う。最初は公開範囲の確認も含めて個別承認し、YouTubeで先頭・中間・末尾の画像・音・同期を確認する。今回は実アップロード未実施。

## リリース・ロールバック

正式公開前に iPhone / 実AUDIO / YouTube取込 / 配布条件を承認し、未解決のCritical・Majorがないことをレビューする。承認後に限りCIと完成物を確認し、通常の配信手順で切り替える。RC1/旧版成果物を先に保管し、バージョンを固定する。

切り戻しは同じオリジンで旧成果物へ。対象タブの書き出しを停止し、必要な完成物を保存したうえで、Service Workerの切替を明示承認する。履歴・設定・素材の照合結果と、既刊ショート・配信結果不明の照合を確認してから制作を再開する。サイトデータの全消去は不要。認証境界・公開範囲・予算およびキーは引き継ぐ。

## 検証記録

- 合成の過去音声と再選択した過去動画の両方から、既存公開本編に紐づくショートを生成。別回同一IDを拒否し、外部HTTPは0回。
- 360p・24fpsを合成音源8秒・15分・90分で検証。90分は187.04秒・86.07 MB・A/V終端差23.2 ms。Linux ChromiumのH.264と開発専用のAACを用いた。
- 未対応コーデックと未対応の保存領域を再現し、編集済み音源が元のバイト列で保存できることを確認。
- 履歴DBを保持したまま2.4.1から3.0に更新し、旧版へ戻す試験を2回確認。Service Workerがページを制御したことを確認してから更新し、待機と操作者による切替を経由。
- ローカルHTTPS隔離環境は57直URLで未認証GET・HEADに401、認証後HEADに200とprivate/no-storeを確認。実ホスティングは未確認。
