# AI STUDIO 3.0 RC1 統合品質保証

## 判定と責務

本番反映は承認待ち。実機、外部の認証境界、配布条件のMajor判定が閉じるまで正式版候補の合格を出さない。

| モジュール | 責務と依存 |
| --- | --- |
| AUDIO | 認証済みの別オリジンに固定素材と編集処理を持つ。明示的なMP3/WAV受け渡しを経由。AIや配信APIに依存しない |
| EDITORIAL | 原音を分析してタイトル・説明文・ショート候補を作る。Geminiアダプターと共通制作IDを使用 |
| SHORTS | 原音区間・字幕・話者・縦型720p/1080pを編集。既存チェックポイントも参照 |
| VIDEO | 編集済み本編の静止画MP4、選抜、承認。配信確認とショートの関連状態をエピソードIDで管理 |
| PUBLISHER | 承認版、権限、配信計画、結果の照合。Driveと各配信の既存境界を維持 |
| BUDGET | アダプターでGeminiを集計し、台帳と予約費用を管理。月額2,000円。制作ロジックの内部に立ち入らない |
| ANALYTICS | 制作・配信・予算台帳を参照。手動取得データを分析し、外部問い合わせは明示実行に限る |

## 本編の設定

360p（640×360）を初期値にする。480p（854×480）と720pは視認性を確認して選べる。画面に合わせて1枚を描き、AVCのキーフレームを1回だけエンコードして2秒間隔で再利用する。構成上の有効フレームレートは長尺で約0.5fps。映像のエンコーダー設定値は順に350/500/750 kbps。実ファイルの平均値は素材とキーフレームサイズによる。音声は映像設定と独立し、従来どおりAAC 96 kbps（モノラル）または160 kbps（ステレオ）、サンプリング周波数を維持する。MP3/WAVをAACにする1回の変換に限定し、EQ・ラウドネス調整は入れない。

AUDIOの入口、ANALYTICS、本編の画面と生成モジュールは初回利用時に取得する。起動時のService Workerの先読みから外し、利用後は通常のキャッシュ制御に従う。制作はローカルで進み、完成ファイルはOPFSへ逐次書き込む。容量不足や未対応のAACは理由を表示して中断する。Chromeでの長尺QAでは試験専用のソフトウェアAACを使用。正式候補のビルドはネイティブAACのみ。iPhone SafariのネイティブAACとWebCodecs対応を受入時に確認する。YouTubeの一般向け推奨フレームレートは低フレームレートを保証しないため、隔離試験後のアップロード検証は別途承認を得る。[YouTube 推奨設定](https://support.google.com/youtube/answer/1722171) · [Safari 26 WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)

## セキュリティ・ライセンス

- 公開ビルドを固定音源、秘密ディレクトリ、資格情報、ソースマップ、未確認AACフォールバックについてCIで検査。非公開ビルドにはService Workerを登録しない。固定音源のあるAUDIOは、HTML・JS・マニフェスト・音源に同じ認証を適用し、共有キャッシュを禁止する。
- 既存のDrive OAuth権限と公開設定を変更しない。Drive保存と受け渡しは模擬経路で確認した。運用中の認証・実際の外部サービスは別の試験項目。
- FFmpegを含むAAC WASMは開発試験だけに残し、公開・非公開のStudio成果物から除外。配布可否は対応ソース、改変の開示、再リンク条件、特許を確認するまで保留。H.264/AACのエンコードはブラウザーが提供する実装を利用し、アプリは同コーデックのバイナリーを配布しない。特許上の運用条件は別途確認する。[FFmpegライセンス](https://ffmpeg.org/legal.html)
- MediaBunnyとMP3拡張はMPL-2.0。既存のLAME 3.100を含むMP3 WASMはLGPL。MIT依存を含め、同梱の文書とバージョン対応ソースを記載した。既存Studio・AUDIOに含まれるLAMEの正確なビルド対応資料、差替え・再リンク方法と配布ルートの最終照合は未完了で、正式公開前の承認項目。[通知](../public/third-party-notices.txt) · [LAME](https://lame.sourceforge.io/license.txt) · [Mediabunny MP3拡張](https://mediabunny.dev/guide/extensions/mp3-encoder)

## iPhoneの非公開受入

### 環境と権限

同梱の試験キットを、本番とは別のLAN内端末で展開する。既存の組織内試験HTTPSを利用できる場合はその正規証明書を使う。接続名に合う、iPhoneが信頼する証明書を用意する。外部にルーター転送を設定せず、LANからのTCP 8443/8444のみを試験端末に許可。StudioとAUDIOは別ポートで別オリジン。起動パスワードはその場で発行し、ファイル・リポジトリには入れない。

```sh
read -rs BRIDGE_RC_PASSWORD
export BRIDGE_RC_PASSWORD
python3 serve-rc-preview.py --root . --bind <LANのIP> --cert <証明書> --key <秘密鍵>
```

ユーザー名は bridge。Safariで認証前にStudioとAUDIOのトップと、AUDIOのJS・station/manifest.json・station/opening.wavを直接開き、401と認証入力を確認する。認証後にStudioの「音声」から https://試験接続名:8444 を入力して保存し、AUDIOを開く。証明書の警告が出る場合は試験用の信頼設定を管理者が確認する。固定音源は試験キットの合成音だけを使う。

### 操作順と合格条件

| 順番 | 操作 | 合格条件 | 記録 |
| --- | --- | --- | --- |
| 1 | 合成の収録を開いてタイトルコールを選び、冒頭・終盤を確認してMP3保存 | OP・導入・ED、無音や音量、先頭と末尾に欠落なし | 操作時間と保存待ち |
| 2 | Studioに編集済みMP3を取り込み、原音とは別に維持 | 再起動しても役割と素材を保持。選択だけでAPIが呼ばれない | 操作数・再起動後の表示 |
| 3 | 通常回とショート0本の回でSpotify文章を確認 | 選抜前でもSpotify作業が可能。ショート0本を正常扱い | 事前承認済み試験APIまたはデスクトップの模擬試験 |
| 4 | 動画化を選択し、360pで書き出す。途中で一度中断し再試行する | タイトル・回番号・ロゴが読め、冒頭・終盤が再生できる。容量エラー時は素材を保持 | 容量・中断復帰・待ち時間 |
| 5 | ショートの字幕・話者を確認し、タイミング修正を反映 | 720p/1080p維持。本編結果不明では関連ショートの引き渡しが保留 | 操作時間と修正回数 |
| 6 | 配信状態、経営分析、予算、履歴と復帰を確認 | 同じ承認版の二重処理を拒否。バックグラウンドから戻る際に完了／失敗が見える | 合否と再試行回数 |

準備15〜30分、短い合成素材の操作確認15〜25分を見込む。長尺書き出し待ち、iPhone実作業時間、ファイル共有時間は別計測。1話5分の実作業目標はまだ未計測。実API・Driveの実保存・YouTube取込・SNS投稿は試験承認後に行う。

## 復旧・ロールバック

1. 書き出し中のジョブを終了し、必要な成果物を端末に保存。既存のバックアップ機能で履歴と設定を控える。キーやトークンはバックアップ対象外。予算・新規台帳は別DBにあり、旧版UIからは参照されない。ブラウザの全サイトデータ削除は行わない。
2. 承認を得て、同じオリジンの配信ファイルを保管済みの旧版へ切り替える。非公開AUDIOの証明書・認証・無キャッシュ設定は維持する。異なる配信先に変更する場合、ブラウザー内履歴は自動で共有されない。
3. 公開版では更新を待機させ、タブの制作が終わってから「更新する」を操作。履歴・キー設定・音源バイトを照合し、配信結果不明の案件は外部で照合してから再開する。
