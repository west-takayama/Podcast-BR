# 画面ごしの検証

`npm test` は部品の正しさを見ます。ここは**出来上がった物**を見ます。
書き出した MP3 のバイト列、切り抜きの音、クリップボードの中身、画面の寸法。

これまで見つかった不具合のほとんどは、ここでしか見えないものでした。
「画面には出ているのに、配信するファイルだけが空」のような状態は、
部品ごとの試験では絶対に捕まりません。

## 走らせ方

```bash
npm i -D playwright            # 1回だけ
npx playwright install chromium # 1回だけ
npm run build
node e2e/run.js                # 全部(10〜20分)
node e2e/run.js patrol-ui      # 1つだけ
```

音声のもとは初回に自動で作られます(`speechlike.wav`, 3MB)。
60分の回を試すときだけ `node e2e/make-long.js` を別途実行してください(303MB)。

## 何を見ているか

| 名前 | 見ているもの |
| --- | --- |
| `load` | 起動の速さ(回線と端末の遅さを模して実測) |
| `polish` | 横のはみ出し、指で押せる大きさ、入力の名前 |
| `heights` | 画面の長さ、1件ずつ消すときの確認 |
| `patrol-ui` | 全タブを開いて、例外・console.error・React の警告が出ないか |
| `shortfall` | 返しきれないときに項目を減らして通せるか、記録が残るか |
| `quota` | 無料枠の上限(429)で待つか、別のモデルへ移るか |
| `photo-leak` | 写真が次の回へ漏れないか、MP3 のタグが消えないか |
| `backup-audit` | 控えに設定が入るか、APIキーが漏れないか、古い控えで上書きしないか |
| `clip-align` | 切り抜きが**頼んだ場所**を切り出しているか |

## 書き方の決まり

- **Gemini への通信はすべて `page.route` で差し替える。** 本物の鍵は要りません
- 応答は**部品が複数に分かれた形**で返す。本物はそう返ることがあり、
  ここを1つにすると実際の不具合を素通りします
- 「落ちなかった」ではなく**出来上がった物**を見る。
  デコードした波形、MP3 のバイト列、画素の色、クリップボードの中身
- 直す前に**まず再現させる**。直したあとに、直す前の版でそのテストが
  落ちることを確かめる(`git stash` して `npm run build`)
